## mcp/main.py

### Fix: Missing comma in tools/list — SyntaxError (CRITICAL)
**Problem:** The closing `}` of the `batch_preview` tool entry at line 790 had no comma
before the `machine_simulate` entry. Python raised a `SyntaxError` at startup, preventing
the entire MCP service from loading.
**Change:** Added `,` after the closing `}` of the `batch_preview` inputSchema block.

### Fix: machine_simulate returned success for nonexistent files (CORRECTNESS)
**Problem:** The handler constructed and returned a simulator URL without checking whether
the file exists in `WORKSPACE_DIR`. Callers received a success response for files that
would 404 when the URL was opened.
**Change:** Added `os.path.isfile(os.path.join(WORKSPACE_DIR, filename))` check before
constructing the URL. Returns a JSON-RPC error if the file is not found.

### Fix: WORKSPACE_DIR defined after use (QUALITY)
**Problem:** `WORKSPACE_DIR` was defined at line 1044, after `mcp_handler` referenced it
at line 812. Works at runtime but violated the module-constant-before-use convention and
confused static analysis tools.
**Change:** Moved `WORKSPACE_DIR = os.environ.get(...)` to the module constants block.

### Fix: import mimetypes inside function body (QUALITY)
**Problem:** `import mimetypes` appeared inside the `serve_file` function body.
Standard library imports belong at module top level.
**Change:** Moved `import mimetypes` to the module-level imports block.

### Perf: Cache _tool_routes() as module-level constant (EFFICIENCY)
**Problem:** `_tool_routes()` rebuilt the full routing dict on every call. It was called
from `_dispatch_tool`, which runs for each step of each batch job — N×M times per request.
The dict is static (reads module-level URL constants).
**Change:** Renamed to `_TOOL_ROUTES` and converted from a function to a module-level
dict literal. All call sites updated from `_tool_routes()` to `_TOOL_ROUTES`.

## linuxcnc-bridge/main.py

### Fix: Double TCP connection per motion command (CRITICAL)
**Problem:** `_require_live_linuxcnc()` opened `LinuxCNCRshClient()` (connection #1),
then called `_linuxcncrsh_status()` which opened a second independent `LinuxCNCRshClient`
(connection #2 with full handshake). `linuxcncrsh` allows only one client at a time,
creating a race condition or outright connection rejection on every motion command.
**Change:** Added `_check_machine_ready(client)` helper that reads `estop` and `machine`
state on an existing open connection. `_require_live_linuxcnc` now uses the already-open
client for the readiness check instead of spawning a second one.

### Fix: Socket leak on failed handshake (CRITICAL)
**Problem:** If `_handshake()` raised inside `LinuxCNCRshClient.__init__`, the socket
opened just before it was never closed — no `__del__`, no context manager, no `finally`.
Each failed connection attempt leaked a file descriptor.
**Change:** Wrapped `self._handshake()` in `try/except` that calls `self._socket.close()`
on failure. Added `__enter__`/`__exit__` to make `LinuxCNCRshClient` a context manager.

### Fix: TCP framing bug in _read_lines (CORRECTNESS)
**Problem:** The read loop exited when `data.endswith(b"\n")`, where `data` is the raw
last `recv()` chunk. TCP is a stream; a newline can arrive split across two `recv()` calls,
causing premature exit or missed data.
**Change:** Replaced `chunks: List[str]` accumulation with `buf: bytes` accumulation.
The loop now breaks when `b"\n" in buf` (checking the full buffer, not the last chunk).
Decodes once at the end.

### Fix: Dead code — _bool_word never called (QUALITY)
**Problem:** `_bool_word(text, true_words)` was defined but had zero call sites.
**Change:** Removed the function entirely.

### Fix: Document alias fields in SpindleParams and GCodeParams (QUALITY)
**Problem:** `SpindleParams` had `spindle_speed` (alias for `speed`) and `state` (alias
for `direction`) with no documentation of which takes priority when both are set.
`GCodeParams` had `gcode` as undocumented alias for `command`.
**Change:** Added inline comments documenting field priority (spindle_speed > speed;
state > direction; command > gcode).

### Fix: CAUTION safety level not enforced (QUALITY)
**Problem:** `check_safety()` only raised on `"DANGEROUS"` and `"CRITICAL"`. Jog and home
are tagged `"CAUTION"` but required no `confirm=True`, making the safety level meaningless.
**Change:** Added `"CAUTION"` to the `check_safety` condition so jog and home also require
`confirm=True`.

## dxf-engine/main.py

### Perf: Cache output_path to avoid calling _workspace_path twice per endpoint (EFFICIENCY)
**Problem:** Five endpoints (`offset`, `transform`, `fillet`, `chamfer`, `array`) called
`_workspace_path(params.output_filename)` twice per request: once in `_ensure_success`
and again in the `return`. Each call performs `os.path.abspath` + path-escape security check.
**Change:** Bound the result to `output_path` at the top of each affected endpoint and
used that variable in both `_ensure_success` and `return`.

## docker-compose.yml

### Fix: Remove hardcoded platform: linux/arm64 from visualizer service (QUALITY)
**Problem:** `platform: linux/arm64` causes a platform mismatch error on x86_64 hosts
without QEMU.
**Change:** Removed the `platform:` line. Docker Compose selects the host's native
platform by default.

### Fix: Create missing ./visualizer/simulador directory (CORRECTNESS)
**Problem:** `docker-compose.yml` mounted `./visualizer/simulador` but the directory was
not tracked in git. Docker created it empty; all STL machine model files returned 404
silently — the 3D machine was invisible with no error at startup.
**Change:** Created `visualizer/simulador/.gitkeep` so the directory is tracked in git.
Place STL models here before running.

## README.md and .env.example

### Security: Remove real Tailscale IP and credentials (SECURITY)
**Problem:** Both files contained the actual Tailscale node IP `100.124.98.116` and
plaintext `linuxcncrsh` passwords `EMC`/`EMCTOO`. Visible to anyone with repository

## visualizer/simulador-web/app.js

### Fix: Remove ineffective linewidth on LineBasicMaterial (QUALITY)
**Problem:** `linewidth: 2` is silently ignored by Three.js on all WebGL backends — a
documented limitation of the WebGL spec. Misleading to anyone reading the code.
**Change:** Removed the `linewidth: 2` property from the cut-path `LineBasicMaterial`.
